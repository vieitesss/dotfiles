# Intercom messages are the subagent result channel

The pi-subagent skill originally returned results purely as files: each child wrote a result artifact and the parent read it. We decided that subagent sessions now deliver results as `pi-intercom` messages instead — every child sends a fire-and-forget `TASK COMPLETE:` completion report to its supervisor when it finishes, and escalates mid-task via `contact_supervisor` when blocked. File artifacts are still written (via the watch window's output capture) but are demoted to crash forensics and follow-up context, not the delivery channel.

The trade-off: immediacy and conversational results (the supervisor sees summaries arrive inline and can reply to blocking questions mid-turn) against delivery durability — if the broker is down or a child crashes before sending, nothing arrives, and silence is treated as the failure signal with `wait`/`status` reconciliation. The broker's delivery ack before process exit makes the happy path reliable, and the pi-intercom package explicitly supports non-interactive children, so the risk was judged acceptable for the gain in supervisor awareness — especially once subagents also live in observable tmux panes.
